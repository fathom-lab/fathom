**pivot:** don't fix hallucinations. FLAG them.

when C_delta spikes above threshold at a key position:
1. detect it ✅ (proven, p=0.020)

## what was built: fathom_monitor.py

file: `sae-reasoning-depth/fathom_monitor.py`

**Fathom Monitor v1 — Uncertainty Flag Layer**

```
input:  any LLM generation
output: per-token C_delta trace + uncertainty flags where C_delta > threshold
value:  tells you exactly which tokens were generated with over-coherent
        (hallucinating) circuits. no correction needed. just transparency.
```

**architecture:**
- wraps `CoherenceSteerer` — single forward pass per token
- two-tier severity: UNCERTAIN (C_delta > 0.010) and HALLUCINATION_RISK (C_delta > 0.020)
- inline annotation format: `"The president[C_delta=+0.0117 — verify this] of Australia is"`
- structured output: `MonitorResult` with flags list, flag_rate, max_c_delta
- CLI: `python fathom_monitor.py "Who invented the telephone?"`

**classes:**
- `FathomMonitor` — main interface
- `MonitorResult` — output container
- `FlagEvent` — per-token flag (idx, token, c_delta, label)

## product spec (Fathom Monitor)

**Fathom Monitor API:**
- input: any LLM generation request
- output:
  - `text`: the generated text
  - `flagged_text`: text with inline uncertainty markers
  - `flags`: structured list of flag events per token
  - `flag_rate`: % of tokens flagged
  - `max_c_delta`: worst-case coherence spike seen
- value prop: tells you WHICH tokens were generated by hallucinating circuits
- differentiator: no other product does this at the mechanistic level

**use cases:**
- RAG pipelines: flag before retrieval (don't retrieve everything, only flagged spans)
- agent loops: catch hallucinated tool calls before execution
- enterprise QA: audit trails for LLM outputs
- model evaluation: per-token uncertainty as a quality signal
